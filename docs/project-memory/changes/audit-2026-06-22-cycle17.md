# Audit Cycle #17 — 2026-06-22 — Notification queue SLA monitoring

## Focus
Surface degraded states of the notification job queue (introduced in cycle #16)
inside the existing admin alerts panel, so operators see backlog/failure spikes
without inspecting the table by hand.

## Changes

- **Migration**: new `public.notification_jobs_health()` SECURITY DEFINER
  function returning `(pending, failed, stuck)` counts. `notification_jobs` stays
  service_role-only; this RPC is the single read surface for authenticated
  callers. EXECUTE revoked from PUBLIC, granted to `authenticated` +
  `service_role`.
  - `failed`  = `status='failed' AND attempts >= 5` (hit retry cap)
  - `stuck`   = `status='sending' AND updated_at < now() - interval '5 min'`
  - `pending` = `status='pending'`
- **`src/lib/alerts.functions.ts`**: extended `Alert.kind` with
  `notification_queue_stuck` and added a `getAlerts` branch that calls the RPC
  and emits an alert (severity `error` if anything failed, `warn` if only
  stuck). Respects the existing `alert_dismissals` snooze table.

## Verification
- `bunx tsc --noEmit` → clean.
- RPC verified via migration linter; no new SECURITY DEFINER warnings
  attributable to this change (REVOKE FROM PUBLIC + explicit GRANT).

## Score impact
No category regression. Enterprise observability ticks up: queue SLA is now
visible alongside webhook failures and membership expirations.
