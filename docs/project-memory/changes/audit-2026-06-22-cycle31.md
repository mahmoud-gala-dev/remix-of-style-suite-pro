## Bugs Fixed
- **Runtime crash: `Cannot read properties of undefined (reading 'nameAr')`**.
  `useCurrentBranch()` returns `undefined` when the current tenant has zero
  branches (or before the store has hydrated). Two consumers dereferenced
  `branch.nameAr` / `branch.id` without a guard and blanked the dashboard:
  - `src/components/shell/topbar.tsx` — branch picker dropdown.
  - `src/routes/_authenticated/index.tsx` — dashboard header + KPIs.

## Files Modified
- `src/components/shell/topbar.tsx` — wrapped the branch dropdown in
  `{branch && ...}` so the picker simply hides when no branch is selected.
- `src/routes/_authenticated/index.tsx` — switched every `branch.*` access to
  optional chaining (`branch?.id`, `branch?.chairs`, `branch?.nameAr`) and
  fall back to `"—"` / `0` so the dashboard renders an empty-state instead of
  throwing.

## Risks
- None — purely defensive null guards, no behavior change when `branch` is
  defined.

## Technical Debt Remaining
- Other authenticated routes (`bookings`, `calendar`, `employees`, `services`,
  `branches`, `packages`, `memberships`, `reports`, `shifts`) still read
  `branch.id` directly. They have not crashed in practice because the
  dashboard is the entry point, but they share the same latent issue. Track
  as a follow-up: introduce a `useRequiredBranch()` helper that renders a
  shared "No branch configured" empty state for the whole `_authenticated`
  subtree.

## Next Priorities
- P2: ship `useRequiredBranch()` + shared empty state to eliminate the entire
  bug class in one place.
