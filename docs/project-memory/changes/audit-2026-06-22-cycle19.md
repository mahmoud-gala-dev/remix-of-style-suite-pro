# Audit Cycle #19 — 2026-06-22 — Realtime Sync

## Focus
Close KI-003 — replace polling with Supabase Realtime across bookings, queue, invoices/payments, and the kiosk display.

## Changes

### DB
- Migration: added `invoices` and `payments` to `supabase_realtime` publication (idempotent guard).
- Set `REPLICA IDENTITY FULL` on `bookings`, `queue_items`, `invoices`, `payments` so UPDATE/DELETE payloads carry full row state (needed for accurate cache reconciliation).

### Client subscriptions
- `src/routes/_authenticated/invoices.tsx`: subscribes to `invoices` + `payments` postgres_changes → invalidates `["invoices"]`.
- `src/routes/display.$branch.tsx`: subscribes to `queue_items` + `bookings` filtered by `branch_id` → invalidates `["branch-display", branch]`. Polling reduced from 5 s to 30 s as a safety net (Realtime is primary).
- `bookings`, `queue`, `calendar` already had Realtime hooks from earlier cycles — no change needed.

### Hygiene
- All channels created inside `useEffect`, torn down on unmount via `supabase.removeChannel()` — matches Realtime billing guidance, no leak.
- RLS still gates row visibility per subscriber.

## Verification
- `pg_publication_tables` now lists: bookings, queue_items, invoices, payments.
- Manual: editing an invoice on one tab updates the list on another within ~1 s.

## Score impact
KI-003 → resolved. Performance category effectively gains a point (no idle 5 s polls on kiosk).
