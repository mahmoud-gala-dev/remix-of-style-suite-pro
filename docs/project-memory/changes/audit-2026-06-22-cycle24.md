# Audit Cycle #24 — Referral Program

Date: 2026-06-24

## Scope

Implements module #4 from the high-value backlog: word-of-mouth referrals with
dual-sided rewards (referrer + referee). Unique per-customer codes with usage
caps and pending → completed lifecycle.

## Database

- `referral_codes` — one unique code per customer per branch (`UNIQUE
  (customer_id)`), `referrer_reward` / `referee_reward`, `reward_type`
  (`credit | points | discount_pct`), `uses_count`, optional `max_uses`.
- `referrals` — ledger of (code → referee), unique on
  `(referral_code_id, referee_customer_id)`, status
  `pending | completed | cancelled`.
- RLS scoped via `branch.tenant_id = ANY(public.current_user_tenants())`.
- `set_updated_at` trigger on `referral_codes`.

## Server functions (`src/lib/referrals.functions.ts`)

- `listReferralCodes`, `issueReferralCode` (8-char A–Z/2–9, retries on
  collision), `redeemReferralCode` (self-referral guard, single-use per
  referee, increments `uses_count`).
- `completeReferral` (marks the referee's qualifying action complete).
- `listReferrals` (branch-scoped).

## Frontend

- `src/routes/_authenticated/referrals.tsx` — issue form, redeem form, codes
  table, referrals table with "Complete" action on pending entries.
- Sidebar entry under Finance (`src/lib/modules.ts`, Share2 icon).
- i18n key `referrals` (en/ar).
